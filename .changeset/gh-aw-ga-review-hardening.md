Hardened the Squad GH-AW (GitHub Agentic Workflows) source contract against nine confirmed GA-review findings:

- **`squad-improvement-gate.mjs`**: closed a test-coverage gap for rejecting a content-only modification of an already-tracked executable (`100755`) Markdown improvement target (the production `ALLOWED_FILE_MODE` guard was already correct; added realistic Git-mode regression/mutation tests).
- **`squad_approval_relay` contract**: made the `squad.md` → `squad-improvement-worker.md`/gate producer/receiver contract for the approval relay payload unambiguous as a JSON string end-to-end, preserving the distinct `squad_approval_relay` input name (gh-aw overwrites `aw_context`). Added compiled assertion/mutation coverage.
- **`squad-review-guard.mjs`**: confirmed and regression-tested that unauthorized/malformed override markers are rejected by authorized-admin-human filtering *before* cardinality/record parsing, so a malformed authorized record still fails closed and an unauthorized marker can never be counted.
- **`squad-planning-ontology.md`**: normalized the result-line template from `Result: ✅ PASS` to the exact `RESULT: PASS` string required by downstream parsers.
- **`squad-install-verifier.mjs`**: confirmed `verifyInstalledBytes()` normalizes only the one documented injected `source:` ownership-binding line before hashing, and fails closed on any other tamper; existing mutation-test table already covers this.
- **Numeric identity canonicalization**: numeric issue/comment IDs arriving via `issue_comment` are canonicalized to safe-integer strings before comparison against `workflow_dispatch` string inputs, with invalid forms rejected; covered by direct and relayed regression/mutation tests.
- **`squad-command-router.md`**: blocked replay of bot-authored standalone `/squad` issue/comment text while preserving trusted `workflow_dispatch` continuation and documented bot command behavior, covering both `created` and `edited` events.
- **`can_approve_pull_request_reviews`**: proved from gh-aw source that this is a single combined toggle gating both `GITHUB_TOKEN` PR creation *and* PR-review approval — it cannot be split via job-level `permissions:`. Per least-privilege policy (no weakened independent-human review gate), flipped to `false` across all public/enlistment/setup copies and added a fallback-to-issue mechanism (with a manual compare-URL link) to `squad-bootstrap.md` for when the push succeeds but the PR cannot be opened.
- **Mutable installation channel**: eliminated resolution of a mutable `commits/dev` ref for GA installs; setup now requires an explicit, pre-validated 40-character `SQUAD_SHA`, synchronized across public/enlistment docs and skill mirrors, while exact-SHA fixture testing remains unaffected.

Also redesigned the `can_approve_pull_request_reviews: false` bootstrap-PR fallback (surfaced by hosted-agent auto-review as a dead end: a plain compare-URL issue could never satisfy the bot-authorship-gated review contract) into a trusted signed-provenance-record path: the bootstrap run stamps a machine-readable provenance line (repo/run/base branch/head branch/head SHA/compare URL) into the fallback issue, and `squad-review-guard.mjs` validates a human-opened Cast PR against that record end-to-end — including bootstrap-run success — before granting the same base-controlled roles as the bot-authored path, with forged/unrelated/malformed records still failing closed.

No stable release is published by this change. Real (non-mocked) `gh aw compile --strict` against the canonical `workflows/*.md` sources continues to produce exactly the two documented warnings (`pull_request_target` advisory on `squad-review.md`, bot-trigger advisory on `squad.md`).

### Follow-up: bootstrap-PR-fallback trust hardening (auto-review on commit `9b45d116`)

- **`squad-bootstrap-validator.mjs`** (`findExistingBootstrapPrFallbackIssue`): a fallback-issue dedupe/ambiguity check previously counted any open issue matching only the plain, unsigned marker substring — any repo participant able to open an issue could post a decoy to suppress the real fallback issue or manufacture an "ambiguous" error. Candidates are now filtered to bot-authored, correctly titled, valid-provenance issues *before* counting/matching. Added forgery-regression tests proving a decoy issue can neither suppress real fallback-issue creation nor manufacture ambiguity.
- **`squad-review-guard.mjs`** (`validateBootstrapPrFallbackAttribution`): the fallback trust path bound a provenance record's `run_id` only to a historical successful run on the same *base-branch name*, unlike the bot-authored path, which also requires `run.head_sha === pr.base.sha`. Added the equivalent binding so a fallback issue can no longer cite an unrelated historical run on the same branch.
- **`scripts/gh-aw-hosted-e2e.mjs`** (`selectBootstrapFallback`): the hosted E2E only matched a plain-text branch marker and a compare-URL substring, not the full signed provenance record production actually requires — a hosted run could report success for a fallback issue production would reject. Added an independently-written `parseBootstrapPrFallbackProvenance` (not imported from the module under test) and rewired `selectBootstrapFallback` to exact-match the full record against an independently-rebuilt expectation, removing the now-redundant plain-text substring check.
- **`squad-command-router.md`**: added direct test coverage (populating `user.type`/`payload.sender.type`, previously never exercised by any fixture) proving the existing bot-authorship block is reachable and enforced for both `created` and `edited` events, with mutation-kill tests for both the author-type and sender-type halves of the check.

Also updated `docs/src/content/docs/guide/gh-aw.md`, `.github/agents.md`, `README.md` (removed a stale, contradictory `@dev`-tracking note left over from before the explicit-`SQUAD_SHA` policy), and all five synchronized copies of `skills/gh-aw-enlistment/SKILL.md` to describe the fallback-issue-first Cast PR flow instead of an unconditionally automatic one.
